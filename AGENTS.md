# universal-agent-extension-template

A template for one cross-framework coding-agent plugin: Agent Plugins 1.0 at the core, per-framework integrations under
`integrations/<framework>/`, native entry files generated from the sources. The sample plugin `todo-tracker` exercises
every component type; adopters delete what they do not need.

## Project Map

```text
plugin.json, mcp.json      <- Agent Plugins manifest (identity and version) and MCP servers: the sources
mcp/<server>/              <- the MCP servers, the only implementation of each capability (Node ESM, zero deps)
skills/, agents/           <- shared skills (procedures that call the MCP tools, plus their own scripts) and subagents
integrations/<framework>/  <- what one framework needs beyond the core: overrides, hooks, commands, rules, Pi extension
.claude-plugin/ .antigravity-plugin/ .codex-plugin/ .codex/ .mcp.json mcp_config.json hooks.json rules/ package.json
                           <- generated by `just generate`; committed; never edited by hand
scripts/, tests/           <- Deno management code: generator, validators, release rules, label sync; tests
openspec/                  <- OpenSpec: config.yaml, specs/<capability>/, changes/ (+ archive/)
docs/, zensical.toml       <- the published documentation site (Zensical, GitHub Pages)
.agents/knowledge/         <- the knowledge base this file routes into
.agents/skills/            <- project skills and OpenSpec's generated skills (Claude Code sees them via .claude/skills/)
.github/                   <- workflows, composite actions, issue forms, PR template, labels
```

## Core Conventions

- Repository content (code, comments, specs, docs, commits, issues, PRs) is English. Talk to the user in the user's
  language, and write plans and plan-mode documents in it too.
- Never add AI or tool attribution (`Co-Authored-By` for an AI, "Generated with …") to commits, PRs, issues, or
  comments; the human who commits answers for the change (`agent-authority.md`).
- `plugin.json` is the only source of the plugin's name, version, and description; a version change merged to `main` is
  a release. Framework fields go in `integrations/<framework>/`, never in a generated file: run `just generate` after
  editing a source and commit the result.
- Every change to plugin behavior starts as an OpenSpec change and waits for `spec:approved` on its pull request;
  archive only on the maintainer's command in the conversation (`spec-workflow.md`).
- Verify a command's syntax from its `--help` or the sources in `references.md` before writing it down; every framework
  fact in `frameworks.md` carries the date it was read.
- A document that disagrees with the code is fixed, listed for decision, or filed as an issue, never only mentioned in
  conversation (`maintenance.md`, Findings outside the current task).
- Do not change `.devcontainer/`, `.pre-commit-config.yaml`, or `.editorconfig` without asking the maintainer first,
  even when a plan lists the change.

| Committing, marking a PR ready, requesting review, archiving, or unsure whether an action is yours       | `.agents/knowledge/agent-authority.md`          |

| Branch names, merge method, PR titles, tags, versions                                                    | `.agents/knowledge/git-workflow.md`             |
| A check is red, or changing a workflow, job name, CI-called recipe, or the release path                  | `.agents/knowledge/github/checks.md`            |

## Development Environment

- The dev container (`.devcontainer/`) provides Deno, Node, just, uv, pre-commit, OpenSpec, Zensical, gh, and the Claude
  Code and Codex CLIs. Antigravity's `agy` and Pi's `pi` are not installed; their smoke tests print the manual steps
  instead (`just smoke <framework>`).
- The repository is public: credentials, tokens, internal hosts, and personal data never enter a file, commit, issue, or
  PR. The pre-commit hooks run gitleaks on each commit; CI runs TruffleHog.
- Handoff notes and scratch files go outside the repository (the session scratchpad or a temp dir).

## Validation

| Check                                                                                              | Command                               |
| -------------------------------------------------------------------------------------------------- | ------------------------------------- |
| Everything CI runs: fmt, lint, types, tests, generated files, plugin sources, specs, harness, docs | `just check`                          |
| Regenerate the native entry files from the sources                                                 | `just generate`                       |
| Only the plugin sources and generated files                                                        | `just validate`                       |
| Only the tests (`just test tests/unit/` for one directory)                                         | `just test`                           |
| OpenSpec strict validation plus config and generated-skill checks                                  | `just spec-check`                     |
| Unarchived OpenSpec changes (`--ready` exits non-zero when one exists)                             | `just spec-status`                    |
| Paths and recipes named by this file and the knowledge base exist                                  | `just harness-check`                  |
| Build the docs site strictly / serve it locally                                                    | `just docs-check` / `just docs-serve` |
| Release rules for a version bump against a base ref                                                | `just release-check --pr origin/main` |
| Installation smoke test for one framework                                                          | `just smoke claude-code`              |
| The sample plugin on this repository                                                               | `just todo-scan --unowned-only`       |

## Workflow

Issue → `gh issue develop` branch → draft PR carrying the OpenSpec change → maintainer adds `spec:approved` → implement,
`just check` → agent marks ready → review → maintainer commands the archive → maintainer squash-merges → a version bump
releases through the Release workflow. The knowledge files above hold the details; this line is only the map.
